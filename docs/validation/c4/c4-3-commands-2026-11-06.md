## Canlı Fortress

Aşağıdaki çağrılar mevcut ARM64 image'larıyla yapıldı. `config` çözümünde image, DDS domain'i, PID paylaşımı, depo bind mount'ları ve boş kanıt dizini denetlendi.

```sh
compose_c43() {
  docker compose -p "$DDS_TEST_PAYLOAD" \
    -f docker/compose/docker-compose.dds.yml \
    -f docker/compose/docker-compose.simulation-check.yml \
    -f docker/compose/docker-compose.simulation-c3-3-3.yml \
    -f docker/compose/docker-compose.simulation-c4-1.yml \
    -f docker/compose/docker-compose.simulation-c4-2.yml \
    -f docker/compose/docker-compose.simulation-c4-3.yml "$@"
}

export ROS_DOMAIN_ID=69
for run in c43-tf c43-confirmed; do
  export DDS_TEST_PAYLOAD="fleet-$run"
  export C43_EVIDENCE_DIR="/tmp/fleet-c43/$run"
  mkdir -p "$C43_EVIDENCE_DIR"
  compose_c43 config --format json > "/tmp/fleet-c43/$run-config.json"
  compose_c43 up --no-build --abort-on-container-exit --exit-code-from backend \
    > "/tmp/fleet-c43/$run.log" 2>&1
  # Aşağıdaki inspect ve docker events sorguları down öncesinde çalıştırılır.
  compose_c43 down
done
```

Başarı işaretleri `C43_STATION_ARRIVED`, `ALL_C4_3_TESTS_PASSED` ve `SIMULATION_SHUTDOWN clean=true`. C4.1 ve C4.2 için [önceki katman ve komutlar](c4-2-commands-2026-11-06.md#c41-ve-c42-canlı-fortress) sırasıyla `fleet-c43-c41` ve `fleet-c43-c42` proje adlarıyla kullanıldı. C3.3.3 koşuları şu şekilde başlatıldı.

```sh
COMPOSE_PROJECT_NAME=fleet-c43-c333 python3 scripts/run_c3_3_3.py --domain 68 --token fleet-c43-c333
COMPOSE_PROJECT_NAME=fleet-c43-high python3 scripts/run_c3_3_3.py --domain 68 --token fleet-c43-high --high-preemption
```

`fleet-c43-high` kritik duruş kontrolünde 1 ile döndü. Sonraki ayrı AUTO koşusu başlatılmadı.

Her proje için container silinmeden önce çıkış, OOM ve Docker sinyalleri alındı. C4.3 dosyalarında bütünlük ve yabancı anahtarlar SQLite içinde ve hostta denetlendi.

```sh
for service in simulation backend; do
  name="$DDS_TEST_PAYLOAD-$service-1"
  docker inspect --format '{{.Name}} exit={{.State.ExitCode}} oom={{.State.OOMKilled}}' "$name"
  start=$(docker inspect --format '{{.State.StartedAt}}' "$name")
  finish=$(docker inspect --format '{{.State.FinishedAt}}' "$name")
  docker events --since "$start" --until "$finish" --filter "container=$name" \
    --filter event=kill --filter event=die \
    --format '{{.Action}} signal={{index .Actor.Attributes "signal"}} exit={{index .Actor.Attributes "exitCode"}}'
done

for run in c43-tf c43-confirmed; do
  sqlite3 "/tmp/fleet-c43/$run/c43.sqlite3" 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
done

npx --offline --yes --package @mermaid-js/mermaid-cli@11.12.0 mmdc \
  -i docs/diagrams/src/parking-reservations.mmd -o docs/diagrams/svg/parking-reservations.svg \
  -c /tmp/fleet-c42/mermaid.json -b white
```

Canlı loglar, başarısız denemeler, ayrı SQLite dosyaları ve Docker kanıtları `/tmp/fleet-c43/` altında tutuldu.

## HIGH duruş incelemesi ve yeniden kabul

Ham kanıt dizini `/tmp/fleet-c43-recovery/`. `c43-high-instrumented` ve `c43-high-rebound` önceki tek örnekli ürün davranışıyla tanı amaçlı çalıştırıldı. İkinci tanıda yeni HIGH gönderimi, bağımsız gözlemci terminalden sonraki örnekleri toplayana kadar bekletildi. `c43-high-fixed` aynı ölçütlerle yeni duruş doğrulamasını çalıştırdı. Her çalıştırmada proje adı ve SQLite dosyası ayrı tutuldu.

```sh
evidence=/tmp/fleet-c43-recovery
mkdir -p "$evidence"
run=c43-high-fixed
project="fleet-$run"
COMPOSE_PROJECT_NAME="$project" python3 scripts/run_c3_3_3.py \
  --domain 68 --token "$project" --high-preemption > "$evidence/$run.log" 2>&1
# Çıkış ve Docker olayları kaydedildikten sonra, down öncesi
docker cp "$project-backend-1:/tmp/c3_3_3_t04-high-e2e.db" "$evidence/$run.sqlite3"
sqlite3 "$evidence/$run.sqlite3" 'PRAGMA integrity_check; PRAGMA foreign_key_check;'
rg 'PREEMPTION_STOP_PROOF|LIVE_PREEMPTION_DIAGNOSTICS|LIVE_PREEMPTION_TERMINAL|SIMULATION_SHUTDOWN' "$evidence/$run.log"
```

İlk odaklı koşu ürün düzeltmesinden önce beklenen üç hatayı verdi. İlk tam host ve Humble koşularında ROS paketindeki bir eski test tek duruş örneğiyle terminal bekledi. Bu test sıralı duruş ölçütünü doğrulayacak şekilde güncellendi ve tam seçkiler yeniden çalıştırıldı.

```sh
export PYTHONPATH=.:backend:ros2_ws/src/fleet_robot_executor:ros2_ws/src/fleet_battery_simulator
python3 -m pytest -q tests/test_executor_state_machine.py -k 'cancel or duplicate_reordered'
python3 -m pytest -q tests/test_executor_state_machine.py tests/test_c43_station_dispatch.py
python3 -m fleet_config config/fleet.yaml
python3 -m pytest -q -rs tests/ ros2_ws/src/fleet_robot_executor/test
python3 -m pytest -q docker/simulation-c3-3-3/test_config.py
```

Humble tam seçkisi önceki Docker komutuyla `fleet-c43-recovery-ros` konteynerinde çalıştı. `docker/simulation-c2-3/test_config.py` ve `docker/simulation-c3-3-3/test_config.py` aynı image içinde ayrı pytest çağrılarıyla çalıştırıldı.
